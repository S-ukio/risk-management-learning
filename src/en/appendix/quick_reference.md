# Appendix B: Parameters and Versions Quick Reference

> Only values explicitly stated in the source are included. Entries labeled "derived" are not conclusions of the source.

## 1. Headers Quick Reference

| Header | Type | Key inputs / role |
|---|---|---|
| `X-Khronos` | Signature | Time anchor; determines the field13 branch from 41.1 onward |
| `X-Argus` | Signature | Device parameters, query, khronos |
| `X-Gorgon` | Signature | khronos + STUB + URL digest + context |
| `X-Ladon` | Signature | khronos + license_id |
| `X-Helios` | Signature | Request context |
| `X-Medusa` | Signature | Collection output, clock slot, field13 |
| `X-Perseus` | Signature | FL, KD, session_uuid |
| `X-SS-STUB` | Plaintext | body MD5 (hex) |
| `X-SS-REQ-TICKET` | Plaintext | Monotonically increasing ticket |
| `X-Tt-Dt` / `X-Tt-Store-Region` | Plaintext | Distribution / storage region |
| `sdk-version` / `x-tt-request-tag` | Plaintext | SDK / request tag |

## 2. Device Identifiers Quick Reference

| Identifier | Generated by | Lifetime | Constraint |
|---|---|---|---|
| `device_id` | Server | Device-level, long-lived | 14–19 digits |
| `iid` | Server | Install-level | Returned at registration |
| `openudid` | Client | Device-level | Fixed after first report |
| `cdid` | Client | Install-level | Uppercase UUID |
| `sec_device_token` | Server | Device-level, long-lived | Used in Perseus / Medusa |
| SDI token | MSSDK | Short-lived | Cached per `device_id + app_version` |

## 3. Registration Flow

```text
1. device_register  → device_id / iid (klink.amemv.com)
2. device_report    → Perseus device report
3. app_log          → first-launch tracking event (Sword encoding, without fingerprint results)
4. get_token        → SDI token
5. activate / activate_record
6. birth()          → account warming flow
```

Clock constraints:

```text
boot_time ≤ first_launch ≤ app_start ≤ request time
```

## 5. field13 Quick Reference

```text
msg52 = query_sm3(32B) || body_md5(16B) || khronos_le(4B)
```

| Item | Old versions ≤40.x | New versions 41.1/41.2 |
|---|---|---|
| slot | Mixed from the 52B content → lower 4 bits | `(khronos ^ 52) & 15` |
| Family count | 3 | 4 |
| Family dispatch | `slot % 3` | `slot & 3` |
| Families | SHA-256 / Whirlpool / MD5 | SHA-256 / Whirlpool / BLAKE2b / MD5 |
| Assembly | Direct 20B | 32B → 16B core + 4B tail → 20B |
| Constants | Static table | Derived by khronos rotation |

> 🧮 Derived: if suite1 (`khronos & 7 == 1`) and the new field13 take effect together, then `slot ∈ {5, 13}` and `slot & 3 == 1`. To be verified by testing.

## 6. Eight-Branch Quick Reference

| slot | Form | Feature |
|---|---|---|
| 0 | Modified AES-CBC (2 rounds) | S-box XOR `0x3d` |
| 1 | Modified AES-CBC (2 rounds) | S-box XOR `0x33` |
| 2 | Modified AES-CBC (2 rounds) | S-box XOR `0x3b` |
| 3 | Modified AES-CBC (2 rounds) | S-box XOR `0x39` |
| 4 | Affine SPN (24 rounds) | Fixed affine parameter table |
| 5 | Second virtual-machine core | Main-state generation + two 24-round reductions |
| 6 | Modified SM4 (24 rounds) | S-box XOR `0x17` |
| 7 | Modified SM4 (24 rounds) | S-box XOR `0x1f` |

> ⚠️ This table conflicts with the 16-branch description of field13; the attribution is to be verified, see 5.2 Q1.
>
> Forward 19B → 32B MAC, reverse 32B → 19B; AES/SM4 branches are padded with 13 `0x0d` bytes.

## 7. Perseus Quick Reference

FL structure:

```text
"0|0|c0|c1|c2|c3|c4|0|0|thread_word"
```

Example vector:

```text
seed = 45884766, k = 418, flags = 511, chain_flags = 3
chain = [45884668, 4230265858, 2147978368, 974138666, 3197775088]
thread_word = 482472847
chain[0] - seed = 98 (0x62)
```

Checksum:

```text
pd, fkd = F(session_uuid, kd)
```

Example: `kd=0`, `session_uuid=861775c1-...` → `pd=815239457`, `fkd=2665330607`.
