# 阅读指南

## 读者假设

这本笔记假设你已经具备：

- Android 逆向的基础：能读 Smali / native 汇编，熟悉 JNI、so 加载与常见加固；
- HTTP 协议基础：请求头、query、body、TLS、HTTP/2；
- 密码学常识：哈希、AES/SM4、HMAC、P-256、protobuf；
- 至少一次端到端协议分析的经验。

不要求你同意原文的结论，但要求你在复现时**逐项验证**。

## 三条推荐路线

### 🟠 全景路线（最快建立地图）

`前言 → 第1章 → 第2章 → 第3章 → 4.1 → 4.8 → 第5章`

适合：第一次接触这个体系，或需要向他人解释整体结构。

目标：能画出“设备层 / 网络层 / 行为层”与七神签名头的关系图，理解注册链路为什么有顺序。

### 🔵 算法路线（深挖字段）

`1.2 → 4.2 → 4.3 → 4.4 → 4.5 → 4.6 → 4.7`

适合：要理解 field13、FL、KD、Gorgon 的具体输入输出。

目标：能说清 41.1 前后 Medusa 的分支选择差异，以及为什么两版不能混用。

### 🟢 工程路线（按链路复现）

`2.1 → 2.4 → 3.1 → 3.2 → 3.3 → 4.1 → 4.7 → 4.8 → 5.1`

适合：在自己的授权实验环境里搭一条最小链路。

目标：能列出“一条请求从设备身份到签名头”的完整依赖，并知道哪些状态必须跨请求持久化。

## 版本速览

| 版本段 | 关键变化 | 本笔记的处理 |
|---|---|---|
| 39.4 ～ 40.x | Medusa 短帧；field13 由内容选分支；三族哈希 | 作为旧版对照 |
| 41.0 | 过渡版本，原文未展开 | 标注待补 |
| 41.1 ～ 41.2 | Medusa v412 长帧；field13 改由 khronos 选分支；四族；Perseus 启用 | 重点拆解 |

> ⚠️ **注意**：版本号不是“越大越新”这么简单。原文明确指出，41.1.0 起的版本配置会同时决定 Medusa 与 Perseus 走哪套链路；用错版本配置，即使单个字段算对，组合也会失败。

## 研究边界

- 只在**你拥有明确授权**的设备、账号、网络与 App 版本上做动态验证。
- 不执行批量注册、养号、刷量、诈骗或规避平台计费。
- 不收集、存储、传播他人的个人信息。
- 发现安全问题，按负责任的披露流程处理，不公开可直接利用的细节。
