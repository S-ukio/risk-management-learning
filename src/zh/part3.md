# 第三部分：注册与信任

> 注册不是“发一个请求”，而是一条有顺序、有时序、有状态的链路。

这一部分按冷启动顺序拆解：

1. 先确定时钟基准；
2. 再走注册链路；
3. 构造注册明文；
4. 拿到两类 token；
5. 完成养号与激活；
6. 用 TrustChain 预热信任。

## 本部分包含

- [第3章 设备注册流程](./chapter_registration/README.md)
  - 3.1 冷启动时序与时钟基准
  - 3.2 注册链路分解
  - 3.3 注册明文体结构
  - 3.4 sec_device_token 与 SDI token
  - 3.5 养号与激活链路
  - 3.6 TrustChain 预热

## 读完你应该能

- 写出 `boot_time ≤ first_launch ≤ app_start ≤ 请求时刻` 的约束，并解释倒置为什么异常；
- 说出六步注册链路的顺序，以及“乱序”为什么不必然失败但会降权；
- 区分 `sec_device_token` 与 SDI token 的生命周期；
- 解释“1 秒内打完注册 + 养号”为什么本身就是异常特征。

> 💡 **关键视角**：服务端不仅看“你发了什么”，还看“你在什么时间、以什么顺序发”。
