# 4.5 X-Perseus：FL 特征链

> 🎯 *“同一组输入永远得到同一组链值，因此可离线复现并可逐字节验证。”*

## Perseus 是什么

原文：

> 41.1 起启用的新一代设备报告，报告的 protobuf 编码核心字段是 FL 与 KD。

两个核心：

- **FL**：从 SDK 启动状态确定性派生的特征链；
- **KD**：SDK 进程内的键值状态，参与会话校验。

本页讲 FL，KD 放在 4.6。

## FL 的结构

原文：

> FL 是从 SDK 启动状态确定性派生的特征链，结构为 9 元素数组加一个请求级 thread word：

```text
FL = [slot0, slot1, chain[0..4], slot2, slot3] + thread_word
字符串形式："0|0|c0|c1|c2|c3|c4|0|0|thread_word"
```

拆开看：

| 位置 | 内容 | 说明 |
|---|---|---|
| 0 | `slot0` | 外部槽位，默认 0 |
| 1 | `slot1` | 外部槽位，默认 0 |
| 2–6 | `chain[0..4]` | 5 个 uint32 链值 |
| 7 | `slot2` | 外部槽位，默认 0 |
| 8 | `slot3` | 外部槽位，默认 0 |
| 9 | `thread_word` | 请求级分量 |

字符串形式中，四个外部槽位默认都是 `0`，链值放在中间，`thread_word` 放在最后。

## 派生输入

原文给出的三元组：

| 输入 | 含义 |
|---|---|
| `seed` | SDK 启动时生成的种子 |
| `k` | 启动轮次 |
| `flags` | 派生标志 |

原文：

> 派生函数以 `(seed, k, flags)` 为输入，产出 5 个 uint32 的链值——同一组输入永远得到同一组链值（确定性），因此可离线复现并可逐字节验证。

这是一个很重要的性质：

- FL 不是随机的；
- 它只依赖启动时的状态；
- 给定 `(seed, k, flags)`，可以独立算出 `chain[0..4]`；
- 因此可以用示例向量做逐字节验证。

## chain_flags

原文：

> `chain_flags=3` 表示 http/ws 回调均已注册，真实 App 启动后即为该状态。

含义：

- `chain_flags` 是一个位标志；
- `3` 表示两个回调都已注册；
- 真实 App 启动后通常就是这个状态；
- 如果模拟环境的 `chain_flags` 不是 3，FL 可能对不上。

## thread_word

原文：

> `thread_word` 是请求级分量，由请求 URL 与 token 地址派生，同一请求内固定，跨请求变化。

| 性质 | 说明 |
|---|---|
| 派生输入 | 请求 URL + token 地址 |
| 作用域 | 请求级 |
| 同一请求内 | 固定 |
| 跨请求 | 变化 |

## fl_slots

原文：

> FL 的四个外部槽位（`fl_slots`）默认为 0，由 SDK 内部状态决定，41.2 实测场景下保持 0 即与实包对齐。

实践结论：

- 默认填 0；
- 不要随意填非零值；
- 41.2 实测场景下 0 就能对齐。

## 完整示例（来自原文）

### 输入（SDK 源状态）

```json
{
  "seed": 45884766,
  "k": 418,
  "flags": 511,
  "chain_flags": 3,
  "http_callback": true,
  "ws_callback": true,
  "fl_slots": [0, 0, 0, 0],
  "query": "version_code=410200&device_platform=android&device_id=3559594890366347&aid=1128&iid=1527634069305532&tt_data=a",
  "license_id": 1588093228,
  "token": "AkZhxlbm-UC3lv4akPhb6BKmG",
  "token_address": 512296902576,
  "khronos": 1795342217,
  "session_uuid": "861775c1-5ed4-47f2-b474-2c51dcd9e43e",
  "kd": 0,
  "vpn": 0,
  "sts": 59,
  "do": 1
}
```

### 派生输出

```text
chain       = [45884668, 4230265858, 2147978368, 974138666, 3197775088]
thread_word = 482472847
FL 字符串   = "0|0|45884668|4230265858|2147978368|974138666|3197775088|0|0|482472847"
lp 字符串   = "2|520830913191|521288087767|2041205042694|512296902576"
```

### 一个可验证的观察

原文：

> `chain[0] = 45884668` 与 `seed = 45884766` 只差 98（`0x62`），可观察到派生首步对 seed 的直接变换；后续链值已完全分散。

这意味着：

- 派生函数的第一步对 `seed` 做了一个可观察的变换；
- 98 的差值可以作为“实现是否正确”的第一个检查点；
- 后续链值迅速分散，适合做整体校验。

<div class="callout note"><span class="callout-title">🔑 关键结论</span>
FL 是确定性的：可以先只验证 `chain[0]` 与 `seed` 的 98 差值，再验证完整的 5 个链值。这样能把“第一步错”和“后续轮次错”分开定位。
</div>
