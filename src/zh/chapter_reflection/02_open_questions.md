## 优先级说明

| 优先级 | 含义 |
|---|---|

## P0：核心链路缺口

### Q1. “八分支”到底属于哪个组件？

- **位置**：4.3 末尾 / 4.4
- **现象**：前面说 field13 有 16 个分支、`slot & 15`、输出 20B；这一段说 8 个分支、`slot & 7`、正向 19B → 32B MAC。
- **可能解释**：另一个组件、另一个版本、或原文混用了“分支”一词。
- **验证思路**：
  1. 回到原文完整版，确认这一段前后的标题层级；
  2. 在目标 so 中定位 `& 7` 与 `& 15` 两处分支选择；
  3. 用授权样本对比输入输出长度（20B vs 32B）。

### Q2. field13 的族映射表缺失

- **位置**：4.3
- **现象**：旧版“按 `slot % 3` 分族”、新版“按 `slot & 3` 分派”之后，具体映射表缺失。
- **影响**：无法确认哪个 slot 对应哪个族。
- **验证思路**：用已知向量反推；或在 so 中定位族分派表。

### Q3. Perseus 的 `F(session_uuid, kd)` 未给出

- **位置**：4.6
- **现象**：原文只给出 `pd, fkd = F(session_uuid, kd)` 和一组示例值。
- **影响**：无法独立复现 `pd` / `fkd`。
- **验证思路**：用多组 `(session_uuid, kd)` 样本反推；或定位 so 中的校验和函数。

### Q4. 41.2 外层检查字的构造

- **位置**：4.4
- **现象**：只说明“由 query SM3 低位与 field13 低位组合而成”。
- **影响**：无法确认报告体外层的完整性校验。
- **验证思路**：对比多组 query / field13 / 检查字样本，确定位宽与组合方式。

### Q5. `search_field13` 的归一化规则

- **位置**：4.3
- **现象**：只说“khronos 归一化后计算”“与通用分支共用算法但调用契约不同”。
- **影响**：搜索场景的 field13 无法对齐。
- **验证思路**：对比同一请求在搜索与非搜索场景下的 field13；定位归一化函数。

## P1：版本与参数缺口

### Q6. 2.3 的“三个 token 入口”

- **位置**：2.3
- **现象**：原文写“对应的 token 下发链路有三个入口：”，冒号后为空。
- **影响**：SDI token 的获取路径不完整。
- **验证思路**：从完整原文或抓包中确认三个入口的调用顺序。

### Q7. 3.1 的时钟基准列表

- **位置**：3.1
- **现象**：只说“一组时钟基准”，列表缺失；已知不等式 `boot_time ≤ first_launch ≤ app_start ≤ 请求时刻`。
- **影响**：无法确认具体字段与容差。
- **验证思路**：从注册体与 Medusa 报告中反推；对比多设备样本。

### Q8. `x-common-params-v2` 的完整 30 键

- **位置**：4.1
- **现象**：原文以代码块列出核心键，未给完整 30 键表。
- **影响**：结构完整性无法确认。
- **验证思路**：抓取真实请求，按顺序枚举；对比不同版本。

### Q9. Perseus `field3.18/19/20` 与 `field4.tk`

- **位置**：4.6
- **现象**：原文只给示例值，未说明含义。
- **影响**：protobuf 结构不完整。
- **验证思路**：对比多组样本；定位序列化代码。

### Q10. `lp` 路径链的生成规则

- **位置**：4.6
- **现象**：只给示例 `"2|520830913191|521288087767|2041205042694|512296902576"`。
- **影响**：无法独立生成。
- **验证思路**：结合 `token_address`、`module_base` 与请求上下文分析。

### Q11. 地址偏移量级不一致

- **位置**：4.6
- **现象**：原文写 `token_address − module_base ≈ 0x4000000` 量级；按给定数值计算为 `0x354FEFFB0`（约 13.3 GiB）。
- **影响**：对“偏移规律”的理解可能偏差。
- **验证思路**：确认数值单位；对比多组样本的差值。

### Q12. 41.0 的变化

- **位置**：1.4
- **现象**：原文覆盖 39.4～41.2，但 41.0 未展开。
- **影响**：版本演进链条不完整。
- **验证思路**：找 41.0 的样本做差分。

## P2：扩展问题

### Q13. X-Argus / X-Ladon / X-Helios 的内部算法

- **验证思路**：单独分析 so；对比输入输出。

- **位置**：3.6
- **现象**：只说“返回内容不重要，重要的是它出现过”。
- **影响**：无法量化预热效果。
- **验证思路**：对比预热 / 不预热的 `empty` 比例。

### Q15. 39.4～40.x 的短帧完整格式

- **位置**：4.3
- **现象**：只给流水线（异或流 → 种子异或 → 魔改 AES → 帧封装），未给字段布局。
- **影响**：旧版无法完整复现。
- **验证思路**：静态分析旧版 so；对比新旧帧长度与字段。

## 建议的推进顺序

```text
Q1（八分支归属）
  → Q2（族映射）
  → Q3（F 函数）
  → Q4（外层检查字）
  → Q5（search_field13）
  → 其余 P1 / P2
```

理由：Q1 决定“你在分析哪个组件”，Q2–Q5 决定“核心摘要链路是否闭合”。这五项不清楚，后面的参数补齐意义不大。
