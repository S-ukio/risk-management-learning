# 第四部分：请求与签名

> 这一部分是全书的算法核心，也是最容易“每个头都对、组合起来错”的地方。

## 本部分包含

- [第4章 核心请求参数拆解](./chapter_params/README.md)
  - 4.1 x-common-params-v2
  - 4.2 X-Khronos 与 suite 对齐
  - 4.3 X-Medusa：两代链路与 field13
  - 4.4 f17 时钟槽、会话结构与八分支疑问
  - 4.5 X-Perseus：FL 特征链
  - 4.6 X-Perseus：KD、校验和与 protobuf
  - 4.7 X-Gorgon
  - 4.8 版本差异与实现约束

## 阅读顺序建议

| 目标 | 顺序 |
|---|---|
| 先看整体 | 4.1 → 4.2 → 4.3 → 4.8 |
| 深挖 Medusa | 4.3 → 4.4 → 4.8 |
| 深挖 Perseus | 4.5 → 4.6 → 4.8 |
| 复现请求绑定 | 4.1 → 4.7 → 4.8 |

## 读完你应该能

- 解释 `msg52 = query_sm3(32B) || body_md5(16B) || khronos_le(4B)` 的每个部分；
- 对比旧版“内容选分支”和新版“khronos 选分支”的差异；
- 说出 Perseus 的 FL 链为什么可以离线复现；
- 解释 KD 为什么必须“进程内共享、跨会话持久化”；
- 说出 Gorgon 如何把请求体绑定到签名上。

> ⚠️ **最重要的结论**：两代 Medusa 算法不能混用。版本号、分支选择、常数派生、输出组装必须来自同一套配置。
