# 2.3 动态指纹：SDI/MSSDK 采集器

> 🎯 *“静态指纹是声明，动态采集是测量，两者必须匹配。”*

## 采集面

MSSDK 的动态采集面可以分成三类：

### 1. 运行时探测

- 已装 App 列表（部分）；
- 传感器实时读数；
- 电池 / 充电状态。

### 2. 环境检测

- root 特征；
- Xposed / Frida 挂钩特征；
- 模拟器特征；
- VPN 状态。

### 3. 行为特征

- 屏幕交互时序；
- 传感器噪声的“真实性”（真机噪声 vs 合成数据）。

## 为什么“测量”比“声明”更难伪造

静态字段可以照抄一台真机，但动态采集要求：

- 传感器读数要符合物理规律（噪声、漂移、量程）；
- 电池 / 充电状态要与时间、使用强度自洽；
- 屏幕交互时序要像人，而不是脚本；
- 环境检测要没有挂钩、注入、模拟器痕迹。

原文用“测量”这个词很准确：服务端不是在读你填的表，而是在看你测出来的数据像不像真的。

## 两条实践要点

原文在 2.3 末尾给了两条很具体的提醒：

### 1. `ri` 报告必须使用本机参数

> ri 报告必须使用本机参数而非外部传入的手机参数——有一类风控交叉检查就是对比 ri 内容与 UA / 静态指纹的机型一致性。

含义：

- `ri` 报告里的机型、分辨率、系统版本，必须来自当前设备的真实采集；
- 不能从外部配置“传进来”；
- 服务端会把 `ri` 内容与 UA、静态指纹比对。

### 2. `raw24` 缺失不应中断链路

> 注册流程中若 raw24 缺失，不应中断 get_token 与 birth 链路（服务端容忍部分字段缺失，但不容忍链路中断）。

含义：

- 某些字段缺失是可容忍的；
- 但链路中断（例如因为缺一个字段就不发 `get_token`）会导致更严重的后果；
- 设计上应该“尽力上报，允许缺字段”，而不是“缺字段就停”。

<div class="callout note"><span class="callout-title">🔑 关键结论</span>
动态采集的核心不是“采到所有字段”，而是“采到的字段彼此一致，且与静态声明一致”。缺字段可以容忍，链路中断和自相矛盾不能。
</div>
