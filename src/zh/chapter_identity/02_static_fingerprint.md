# 2.2 静态指纹：机型模板

> 🎯 *“静态指纹的风险点不在单个字段，而在组合合理性。”*

## 静态指纹是什么

静态指纹是设备的“硬件声明”，它在注册时一次性上报，后续保持一致。

原文列出的类别：

| 类别 | 内容 |
|---|---|
| 硬件参数 | 品牌、机型、主板、codename、硬件名（`ro.product.*` 系列） |
| 系统参数 | Android 版本、API level、ROM 构建、内核 |
| 显示参数 | 分辨率、dpi、notch / 刘海信息 |
| 传感器集合 | 加速度计、陀螺仪、磁力计的存在性与量程 |
| ABIs 与 CPU 拓扑 | `arm64-v8a` 支持、核心数、频率档位 |

## 为什么组合比单字段重要

单个字段很容易伪造：随便填一个品牌、一个分辨率，都能“看起来像”。

真正难的是**组合自洽**。原文给了两个例子：

### 例子一：分辨率与 dpi 矛盾

- 分辨率 `1080×2400`；
- dpi 写 `480`。

问题：`480 dpi` 通常对应 1440p 级别的机型，而不是 1080p。采集器会把这两个字段放在一起看，发现它们不属于同一类设备。

### 例子二：API level 与 ROM 字符串矛盾

- API level 写 `33`（Android 13）；
- ROM 特征字符串却是 Android 12 的。

问题：系统版本与 ROM 构建信息不一致，说明这份指纹不是从一台真实设备上完整采集的，而是拼出来的。

## 采集器怎么做交叉验证

可以把静态指纹的验证理解成三层：

1. **字段级校验**：长度、字符集、枚举值是否合法；
2. **组合级校验**：分辨率 ↔ dpi ↔ 机型、API ↔ ROM ↔ 内核、ABI ↔ CPU 拓扑；
3. **声明级校验**：静态指纹 ↔ UA ↔ `x-common-params-v2` ↔ 注册体，四处是否一致。

<div class="callout warn"><span class="callout-title">⚠️ 常见错误</span>
只对齐 UA，不对齐注册体和 `x-common-params-v2`。服务端会把它们放在一起比对，任何一处不同都会扣分。
</div>

## 机型模板的工程含义

如果你要构造一个可复现的实验环境，静态指纹不应该“随手编”，而应该：

- 选定一个真实机型模板；
- 把该机型的 `ro.product.*`、分辨率、dpi、API、ABI、传感器集合整理成一份配置；
- 让 UA、注册体、`x-common-params-v2`、后续采集全部引用同一份配置。

这就是“机型模板”的思路：**一个配置源，多处引用，保证一致**。
